# ML-Builder

ML-Builder is a command-line AutoML tool for CSV and Excel datasets. It
validates and splits the data, adapts the search to available resources,
screens candidate models, trains the strongest candidates, evaluates them on a
held-out test set, and saves a reusable sklearn pipeline.

## Install

Python 3.12 or newer is required.

```powershell
uv sync
```

Optional model and reporting dependencies can be installed with:

```powershell
uv sync --extra boosting --extra reports
```

Image datasets require the vision extraction dependencies:

```powershell
uv sync --extra images
```

Explicit image splits are supported:

```text
dataset/
  train/
    cats/
    dogs/
  test/
    cats/
    dogs/
```

If `train/` and `test/` exist, they are used as supplied. An optional `val/`
folder is added to the downstream development set.

Explicit splits are not required. For a class-folder dataset such as
`dataset/cats` and `dataset/dogs`, ML-Builder first performs a stratified
development/test split using file paths. The test paths are reserved before
any adapter or embedding model sees them.

Run `python main.py --adapt-lora` to enable adaptation. The adapter trains only
on development paths and creates its own stratified validation subset for
early stopping and best-checkpoint restoration. AdamW weight decay is applied
to trainable parameters, and final testing always uses the untouched test
paths.

## Run

The only application entrypoint is `main.py`:

```powershell
uv run python main.py path\to\data.csv --target label
```

You can omit the dataset argument and enter its path when prompted:

```powershell
uv run python main.py --target label
```

Running without arguments is also supported:

```powershell
python main.py
```

The CLI asks for the dataset path first. For CSV or Excel input, it then asks
for the target column. For an image directory, labels are inferred from class
subfolders and no target is requested:

```text
images/
  cats/
    cat-01.jpg
  dogs/
    dog-01.jpg
```

After installing the package, the equivalent command is:

```powershell
ml-builder path\to\data.csv --target label
```

Common options:

```powershell
# Select models and cap training time
uv run python main.py data.csv --target label --models logistic,rf,gb --max-time 10m

# Force regression and enable safe feature engineering
uv run python main.py data.xlsx --target price --problem-type regression --feature-engineering

# Tune the best models and generate a report
uv run python main.py data.csv --target label --tune --report --shap
```

Run `uv run python main.py --help` for every option. The command is
non-interactive; no source-code edits or prompts are required.

## Outputs

Each run writes to `artifacts/` by default:

- `best_model.joblib`: fitted preprocessing and model pipeline
- `metrics.csv`: held-out evaluation metrics for every trained model
- `run.json`: reproducibility manifest with accuracy, runtime, RAM, and VRAM metrics
- `report/`: optional EDA, explanation, and HTML report files

Change the location with `--output-dir`.

## Behavior

- The problem type is inferred from the target and can be overridden with
  `--problem-type`.
- Resource-aware defaults limit expensive models and feature expansion.
- LightGBM and XGBoost are optional. The CLI continues with sklearn models
  when either package is unavailable.
- Classification keeps candidates from GBDT, linear, and nonlinear model
  families. A diverse probability ensemble is deployed only when it improves
  training-only validation accuracy without contradicting cross-validation.
- Temperature scaling is fitted on training-only validation probabilities.
  It improves probability calibration/NLL without changing predicted classes.
- Reports, plots, Markdown explanations, and notebooks are generated by
  default. Disable them with `--no-report`, `--no-llm`, or `--no-notebook`.
- Feature engineering, tuning, and SHAP are opt-in.
- Invalid files, targets, durations, fractions, and unusable datasets fail
  early with actionable messages.

Research modules for memory learning and multimodal experiments remain in the
repository as internal components, but they are not part of the stable CLI
contract.

## Test

```powershell
uv run pytest
```

Pytest is intentionally scoped to `tests/`; historical executable experiment
scripts are not collected as tests.
